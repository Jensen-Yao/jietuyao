## 八A、性能优化记录（M9）

| 优化 | 内容 | 实测基线（已固化为回归上界） |
|---|---|---|
| 取色 O(1) 化 | 会话缓存冻结图像素字节数组，GetPixelAt 直读数组（刷新背景自动重建） | 10 万次读取 15ms（≈150ns/次），20 点抽样与 GDI+ 逐像素一致 |
| GIF 采集/编码管线 | BitBlt 采集线程与 JPEG 编码线程解耦（缓冲池+有界队列，满则丢帧保节奏），消除每帧位图分配与 GC 压力 | JPEG 640×480 仅 0.5ms/帧（GDI+ x64 很快；管线价值在 4K/高帧率下的节奏保证） |
| 编解码器静态缓存 | JPEG/GIF ImageCodecInfo 查一次（原每帧 LINQ 枚举系统编码器表） | — |
| 编辑器渲染热路径 | 遮罩/手柄/高亮/悬停的画刷画笔全部静态冻结（原每帧 new+Freeze） | — |
| SQLite | WAL 模式（监听写入与窗口查询并发不阻塞）+ group_id 索引 | — |
| 冻结图→WPF源 | 既有路径基线记录 | 1080p 42ms（编辑器打开一次性） |
| Release 启动 | 实测 3.3–3.6s / ~195MB（当前高负载机器，含 24 插件扫描；v1 同窗口 90s 未达加载阈值） | — |

  （合成 HELLO 2026 → 命中；双行 → SECONDLINE 命中+阅读序断言）
- **本轮测试抓出并修复 3 个真实 bug**（此前仅冒烟未暴露）：
  1. GIF 导出：.NET 下 PropertyItem 无公共构造 → 运行时必崩（MissingMethodException）
  2. GIF 帧解码：GDI+ 位图惰性持流，流提前释放致 SaveAdd "常规错误" → 改急切拷贝
  3. PP-OCR：DenseTensor 单下标是 N 维索引非扁平索引 → 检测输入全错（越界）→ 改 Buffer 扁平写
- 拼接兜底统一为 35% 盲拼（含搜索空间过小的早退分支）
- **已知精度边界（如实记录）**：PP-OCR 简化 DB 后处理（轴对齐框+近似外扩）对贴边/细长
  文本可能裁切不完整（合成双行测试中 SECONDLINE 完整、FIRSTLINE 出现残片）；
  完整 DB 多边形 unclip 列为后续增强项
- **启动对比（同机同负载，方法学诚实）**：v2(Debug) 到"启动完成" 3.5–4.1s、内存 121MB；
  v1(PySide6 onefile) 同窗口 90s 未达加载阈值（onefile 每次解压+框架+OCR 预载）、内存 154MB。
  绝对值受机器负载影响，方向性结论：v2 显著更快更省
